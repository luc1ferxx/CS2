# 前端体验审查与改版方向

审查对象：当前本地 CS2 Demo Coach，比赛库 → Nuke / xelex 复盘 → 展开建议 → 观看已有第一人称片段。主桌面视口 1440 × 1000；另记录了当前较窄窗口的实际显示。截图和交互均来自本轮运行，没有使用旧截图代替。本轮不修改 App 代码、比赛或视频。

## 结论

主要问题是信息优先级和任务路径。系统状态、身份表单、历史任务占用了主要空间，画面、播放控制和建议被分散在长页面上。深色基调与 CS2 画面可以保留；先重组布局，再统一文字、间距和色彩。

目标主流程：选择比赛 → 找到值得复盘的一刻 → 同屏观看画面和建议 → 查看下一条。已匹配 xelex 时直接进入复盘，不重复要求确认身份。

## 本轮实际操作与证据

### 1. 比赛库：可用，但进入比赛的优先级低

![比赛库首屏](../output/playwright/ux-01-dashboard.png)

- 四场比赛保留且可以打开，真实 `.dem` 上传入口可见，这是可保留的基础。
- 第一场比赛从页面第 817px 才开始显示。未连接的 Steam 配置区占据首屏中央，包含多个空状态、连接字段和不可用说明。
- 上传与 Mock sandbox 并列；API、active jobs、parser intake 等工程信息需要用户额外理解。
- 用户已有比赛时，首页应直接显示比赛列表和“继续复盘”。“上传比赛”为主要按钮；示例入口明确标注模拟数据并弱化。Steam 放进折叠的导入选项或设置，保留功能。

### 2. 进入复盘：画面大，但控制和建议在首屏之外

![复盘页首屏](../output/playwright/ux-02-review.png)

- 玩家正确匹配 xelex，已有视频能加载，比赛/回合信息可识别。
- 当前桌面页面高约 3067px。身份输入和选择面板位于顶部；画面从约第 470px 开始。
- 保存的片段历史插在画面与主播放控制之间。本次主播放按钮位于约第 1579px；片段越多，距离越远。
- 视频头部同时显示 ready、Clip completed、生成片段和 Mock Render Job，状态与动作缺少清晰主次。
- 改为紧凑比赛栏、“主回放 + 建议”两列，播放条紧贴画面下方。片段库改为播放器附近的次级标签或抽屉，失败记录放入任务详情。

### 3. 阅读建议：信息真实，但说明和操作藏得太深

![展开建议](../output/playwright/ux-03-finding.png)

- 建议提供明确的改进方向与证据局限，地图也能同步显示当前状态，应保留这些能力。
- 默认卡片优先展示 rule ID、tick、关联事件 ID 等字段；用户关心的“发生什么、下次怎么做”需要展开后阅读。
- 说明、技术证据、状态和按钮共同堆在一个密集区域，部分标题被截断，区域还存在内部滚动。
- 默认卡片展示“问题标题 + 一句改进建议 + 第几回合/时间 + 查看这一刻”。技术证据置于“查看依据”折叠区，事实与规则推断、未知条件仍需明确区分。

### 4. 点击观看已有片段：开始播放，但用户看不到视频

![点击观看之后的可见区域](../output/playwright/ux-04-watch-action.png)

- 实际点击 `View clip for this event` 后，视频成功开始播放，地图/时间坐标同步变化。
- 页面仍停留在建议区域，scrollY 为 1662。视频相对视口顶部约为 -1192px，底部约为 -415px，整个视频在可见范围之外。
- 这是最高优先级的体验问题。同屏布局能直接解决；窄屏则需要观看动作把视口和键盘焦点带到回放区，同时保留返回原建议的位置。

## 推荐的信息结构

### 我的比赛

1. 页头：我的比赛、上传比赛、次级示例入口。
2. 简洁的搜索与筛选，可折叠更多条件。
3. 比赛列表：地图、对阵、日期、xelex 的待复盘数量、进入复盘。
4. 重命名、归档进入每行的更多菜单；导入设置和开发工具进入次级区域。

### 复盘工作区

- 顶部一行：返回比赛库、比赛名称/地图、正在复盘 xelex、切换玩家。
- 桌面主体左侧约 70%，右侧建议栏约 30%（约 320–380px），宽度不足时切换单栏。
- 左侧主画布可切换战术回放与第一人称。没有覆盖当前时刻的视频时显示可用的战术回放，并提供生成视频入口。
- 播放/暂停、倍速、前后建议紧贴画面；下方接同一条时间轴和精简回合条。
- 右侧默认显示少量优先复核的建议，同时保留“全部建议”和筛选。不要把规则候选说成已经证明的失误。
- 视频生成动作按状态显示“生成视频 / 等待生成 / 生成中 / 观看视频 / 重试”。现有可播放片段与另一任务的失败要明确分开。
- 片段历史、完整证据、校准、Mock 和诊断放入次级入口，保存功能及 QA 能力。

## 视觉方向

建议以专业深色为默认方向，后续可根据用户偏好调整：

- 保留炭灰/深蓝灰背景；减少网格纹理、全大写标签和重复描边。用分组、留白、字体大小建立层级。
- 只用一种主强调色表示当前动作和选中项；红色表示需要处理的错误，绿色只表示完成状态。地图上的队伍色保留其语义。
- 正文以 14–16px 为基准，辅助文字建议至少 12px。当前一些规则/元信息仅 8–9px，不宜承载关键任务信息。
- 采用一致的 8/16/24px 间距和适度圆角，按钮层级控制为主按钮、次按钮、文字操作。
- 面向当前中文用户统一文案：“我的比赛、重点建议、查看这一刻、生成视频、查看依据”。普通界面使用“第 2 回合 · 0:44”表达位置，原始 tick 放到详细信息。
- 小窗口不把所有按钮排成同等权重的整行。保留播放主操作和简洁状态，其余动作进入菜单。

## 可访问性风险与边界

本轮确认部分辅助文字为 8–9px，若干按钮高度约 28–36px，时间轴标记高度约 16–20px。建议扩大有效点击区域，保证清晰的键盘焦点，并让文字/图标共同表达状态。尚未做完整键盘遍历、读屏、200% 缩放或对比度合规检测；这些属于改版后的必要验证，不据截图宣称合规或不合规。

## 实施顺序与验收

1. 先改复盘页结构：画面、播放控制和当前建议同屏；历史与高级工具不推开主操作。
2. 再改比赛库和文案：上传/进入比赛优先，Steam 和开发项降级，中文任务用语统一。
3. 最后统一颜色、字体、间距、焦点和窄屏适配。

验收目标：在 1440×900 视口不滚动即可播放/暂停并阅读一条建议；已有比赛的用户首屏能看到比赛；一键查看对应时刻；生成状态变化不抢走当前片段；回合、地图、时间轴、POV 和视频继续共用原有状态；窄屏、键盘和失败恢复可完成同一主流程。该优化主要集中在前端，无需重做解析和录制后端。

本轮证据日志：`.local/qa/ux-01-dashboard-result.log`、`ux-02-review-result.log`、`ux-04-watch-action-result.log`。源码结构同时检查了 Dashboard、PersonalReviewPanel、FirstPersonReplay、ClipLibrary、CoachingPanel、CoachingEventCard、Timeline 和 VideoSetupPanel。
