# 可下载安装的桌面版：交付目标

更新日期：2026-09-13。用户明确目标是让其他人像普通软件一样下载安装使用，**首发 Windows，剩余日常开发在 Mac 完成**。下一阶段以首次安装和完整使用流程作为交付重点；已有 Web 复盘与解析能力继续复用。macOS 不承担真实 CS2 视频生成，开发迁移见 [Mac 开发与 Windows 发布](macos_development_windows_release_v1.md)。

## 第一版必须达到的使用体验

1. 用户从发布页下载正式安装包，完成安装后从应用图标打开。
2. 用户无需克隆代码、打开终端、安装 Docker/Python/数据库，或填写 API 地址。
3. 首次启动明确说明是否需要联网、比赛文件存放在哪里，并提供导入 `.dem` 的直接入口。
4. 导入真实比赛后可以看到处理进度，选择本人，查看战术回放、回合、时间轴和有依据的建议。
5. 关闭再打开后仍能找到比赛和复盘位置；升级保留用户数据。
6. 文件无效、服务不可达、解析失败和空间不足等情况有可理解的提示和恢复操作。
7. 用户可以查看版本、获取更新、管理比赛和存储；卸载时明确用户数据的保留策略。
8. 在没有开发环境的另一台电脑上从安装包完成以上流程，才算可分发版本通过验收。

首版核心验收不依赖新视频生成。已有视频可播放；真实 CS2 片段继续由独立 Windows 渲染设备处理，后续通过服务连接。

## 已确定的平台与待定的处理方式

- 首发平台：Windows；Mac 是开发电脑。本阶段无需制作 macOS 安装包。
- 处理方式：联网客户端连接我们维护的服务，或核心解析和复盘离线运行。

处理方式尚待用户选择，不能将“下载安装”默认理解为“必须离线”。依据现有服务架构，联网版可以复用更多已有能力，但需要维护正式服务；离线版需要新增本地运行模式。

## 两条可行路线

| 路线 | 需要完成的工作 | 使用边界 |
| --- | --- | --- |
| 联网桌面客户端 | 打包桌面入口，接入正式 HTTPS 前端/API；完成登录、私有数据、数据库、队列、存储和服务部署验收；统一安装、更新和错误提示。 | 用户不用配置开发环境，核心处理需要联网；我们维护服务运行与成本。 |
| 本地解析桌面版 | 打包界面与各系统的解析器；提供本地应用数据目录、数据库迁移、后台任务管理、启动退出与恢复；避免要求用户安装现有 Postgres/Redis 服务。 | 核心复盘可以离线，安装包和跨平台兼容工作更多；云账号与本地身份需要明确分离。 |

基于现有 Next.js/React 界面，Electron 是优先评估的桌面方案。它提供跨平台打包、签名和更新相关能力，但桌面窗口本身不解决后端依赖。Next.js 的动态比赛路由也不能未经适配直接当成静态页面打包。参考 [Electron 发行说明](https://www.electronjs.org/docs/latest/tutorial/distribution-overview)。

联网首版优先考虑加载我们部署的同源 HTTPS 前端，保留现有登录和私有媒体的同源约束。若改成内置界面跨源访问 API，需要单独设计桌面登录、回调和会话流程。离线版需要新的本地运行模式，不能通过换数据库地址、复用开发身份或要求用户安装 Redis 来完成。

## 实施顺序

1. 在 Mac 跑通开发环境并确认联网/离线处理方式，将 Windows 首版范围固定为“安装 → 导入 → 解析 → 个人复盘 → 重新打开”。
2. 完成桌面入口和选定后端连接/生命周期管理，复用现有真实解析和复盘功能。
3. 处理首次启动、用户数据目录、退出/崩溃恢复和错误提示。
4. 配置 Windows CI 生成安装包，明确版本、签名和更新策略；开发者可继续在 Mac 提交代码。
5. 完成 Windows 签名与下载发布准备，在干净 Windows 设备验证最终安装包和升级后的数据保留。

安装流程完成后，再继续建议去重排序、地图校准和更多真实样本验证。当前 `Start CS2 Coach.cmd` 是已配置开发电脑的入口，不能替代面向普通用户的安装包。
